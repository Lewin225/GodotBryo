# Terrain Streaming v1.5 — implementation completion report

Date: 2026-08-27

Implementation branch: `issue-19-terrain-streaming`  
GodotBryo: `45e3f47`  
Terrain3D submodule: `e7e3d41` on its matching Issue 19 branch

## Status and acceptance boundary

The Phase 0–4 CPU/runtime implementation is complete for the single-master
`FalloutNV.esm` scope. Terrain is owned by a scene-authored `TerrainStreamer`,
composed by native detached workers as complete regions, published into a fixed
Terrain3D domain, filled to finite completion, and retained independently over
base-game Mojave worldspace transitions.

This is not a declaration of full graphical v1.5 acceptance. The required
real-renderer clipmap, GPU-memory/fill-time, collision/grass appearance,
player-driven door, and controlled vanilla silhouette validation has not been
performed. Those are explicit blockers, not evidence inferred from headless
tests.

## What was implemented

### Phase 0 — capability gates, census, and baseline

- Audited Terrain3D: `region_map_changed` rebuilds global collision, while
  `DYNAMIC_GAME` collision is camera-local. This established that ordinary
  streaming publication must not alter the region map.
- Completed the WastelandNV native census: 16,388 usable first-LAND payloads,
  292 touched regions, 18×18 fixed region rectangle, and 80 LTEX identities.
- Recorded a 49-cell Goodsprings cold/warm legacy `import_cell()` baseline
  including LAND lookup, texture resolution/decode/pool insertion, pixel
  writes, publication, collision, and grass binding.
- Implemented and tested the shared-sample rule: select the lexicographically
  lowest usable `(x,y)` LAND owner for an edge/corner sample, falling through
  across gaps. The selected owner supplies every map field together.
- Added fixed-domain Terrain3D APIs and tests proving one initial region-map
  build, then eight map-layer updates with no later `region_map_changed` or
  global collision rebuild.

### Phase 1 — ownership extraction and lifecycle

- Added `TerrainStreamer` as a direct `game.tscn` sibling of `CellLoader` and
  `WorldStreamer`.
- `Game._enter_tree()` opens one main-thread `EsmReader`, builds one
  `GamebryoMeshResolver`, and injects both into all three loaders before their
  `_ready()` work. Standalone loader fallback setup remains available.
- Moved Terrain3D, bridge, texture pool, grass, active-camera binding, timing,
  collision refresh, diagnostics, and pause behavior into `TerrainStreamer`.
- Removed `use_terrain3d`, per-tile `TerrainRoot`, the legacy terrain branch,
  `CellStreamBuilder.build_terrain()`, and exterior terrain ownership from
  `WorldStreamer`/`CellLoader`.
- `WorldStreamer` now has exactly one executable terrain interaction:
  `request_terrain_priority(coord)`.
- Implemented the planned lifecycle API: `configure`, `activate`,
  `deactivate`, `set_paused`, `request_terrain_priority`, `await_ready_for`,
  and `get_diagnostics`.
- `READY` requires collision-area commitment, installed texture mappings,
  collision refresh on the bound camera, and one physics frame. It supports
  cached ready results; pause yields `CANCELLED`, and replacement/teardown
  yields `SUPERSEDED`.

### Phase 2 — native detached complete-region staging

The separate first-party `native/terrain_streamer` GDExtension implements:

```text
open_esm(path)
index_worldspace(worldspace_form_id)
compose_region(worldspace_form_id, region_location, logical_slots)
```

- Every worker owns its own non-thread-safe `EsmFile` and a reusable catalogue
  of usable first-LAND payloads. It does not scan/decode LAND per output pixel.
- Logical LTEX slots are frozen from unsigned FormID order; zero is reserved
  and catalogues above 127 identities are rejected.
- A region writes eight contiguous 256×256 buffers: height/control `RF`; color,
  ID A/B, weight A/B, and normal `RGBA8`.
- Composition preserves the bridge's row/Z flip, N=7 authored ordering,
  strongest-overlay fallback, VCLR alpha, signed VNML conversion, and
  computed-normal fallback. Images are constructed only after buffer completion.
- Workers never receive Terrain3D, texture-pool, rendering, physics, grass, or
  scene objects. Main-thread handoff resolves used LTEX identities, installs
  the render LUT, publishes once, and applies local collision/grass work.
- Stale pause/deactivate/superseded results are rejected and detached tasks are
  reaped without touching scene-owned resources.

### Terrain3D fixed publication

The Terrain3D fork adds:

- `initialize_fixed_region_domain(locations)`: validates bounds/duplicates,
  sorts row-major `(y,x)`, makes canonical blank eight-map regions, and
  builds the region map and arrays exactly once.
- `publish_region_maps(location, maps)`: accepts exactly eight valid maps for
  an already allocated location, replaces that region's maps, updates existing
  array layers and cached height range, and rejects unknown/malformed input.

Steady-state publication does not dirty or emit `region_map_changed`; global
collision rebuild is therefore not triggered by ordinary terrain streaming.
The Terrain3D Issue 19 branch README documents this contract.

### Phase 3 — continuous finite-domain fill

- Complete regions are authoritative and progress through
  `unseen → queued → preparing → prepared → committed`; invalidated work is
  `cancelled`. Cells are a readiness/diagnostic view and commit only after all
  regions that own their samples commit.
- Queue seeding uses the native real-region catalogue, not an unbounded spiral.
- Worker target is `clamp(processor_count - 1, 1, 8)`; main-thread publication
  defaults to one prepared region per frame.
- Crossing a camera cell recomputes distance priority. Hints update an existing
  entry without duplication. Every fourth dispatch reserves a slot for far work.
- Stationary WastelandNV streaming reaches 292/292 regions and zero
  queued/preparing/prepared work; later movement causes no new staging/upload.
- Texture assets resolve lazily. The absent `Landscape\\BurntGround01.dds`
  intentionally uses the existing pink missing-asset fallback so its logical
  mapping remains valid.
- Grass catalogue discovery is separate from local coverage. Emitters exist
  only for committed near-camera identities; materials bind once; coverage
  updates batch emitting-state changes.

### Phase 4 — retained Mojave-family runtime state

`TerrainStreamer` keeps a registry by worldspace FormID. An entry owns its
Terrain3D, bridge, texture pool, grass controller, catalogue, logical slots,
fixed maps/arrays, queue/progress state, generation, residency, worker-stager
state, diagnostics, and cache family. Terrain maps and texture bindings are
not shared between entries.

Cache membership is explicit EditorID configuration, not FormID-prefix
inference. The catalogue covers all twelve terrain-owning base-master
worldspaces: `TestMap01`, `WastelandNV`, Freeside/Gamorrah/Greenhouse
subworlds, Strip/Fort/Boulder City subworlds, `WastelandNVmini`, and
`Lucky38World`.

On pause/switch the active entry advances generation, rejects stale waiters and
results, cancels nonterminal work, hides Terrain3D, disables physics/dynamic
collision, and stops every grass emitter. Resume restores the camera,
visibility, physics, collision, grass processing, coverage, covered emitters,
and only unfinished queue work under a fresh generation. A
`WastelandNV → FreesideWorld → WastelandNV` round trip retains object identity,
map bytes, slots, maps, and texture assignments without restaging LAND.

### Diagnostics and debug UI

- The existing World Streaming tab remains functional and reads terrain
  summary/texture diagnostics through `TerrainStreamer.get_diagnostics()`.
- Added a scene-authored **Terrain Streaming** debug tab. It displays state,
  cache family/worldspace, region commitment, queue/worker activity, resource
  and collision counters, p95 staging/publication/handoff timing, retained
  worldspaces, and live `regions_per_frame`/near-radius controls.
- Phase reports and a local Issue #19 comment draft were added. The comment was
  deliberately not posted externally.

## Measurements

All figures are headless/dummy-renderer CPU measurements on Godot 4.7.1,
Linux x86_64, Ryzen 7 9800X3D, and 30 GiB RAM. “Upload” means the CPU resource
call, not GPU completion.

### 49 real Goodsprings cells: legacy importer

| Stage | Cold p50 / p95 / max | Warm p50 / p95 / max |
|---|---:|---:|
| LAND lookup | 0.10 / 0.13 / 0.14 ms | 0.10 / 0.12 / 0.14 ms |
| LTEX resolution | 0.02 / 24.61 / 176.55 ms | 0.02 / 0.02 / 0.04 ms |
| texture-pool insertion | 0.00 / 22.71 / 56.09 ms | 0.00 / 0.00 / 0.00 ms |
| CPU pixel writes | 3.13 / 3.52 / 3.97 ms | 3.13 / 3.31 / 3.33 ms |
| Terrain3D publication | 0.53 / 1.10 / 2.06 ms | 0.52 / 1.06 / 2.05 ms |
| collision refresh | 0.01 / 0.01 / 0.02 ms | 0.01 / 0.01 / 0.01 ms |
| grass discovery/binding | 0.23 / 0.92 / 11.87 ms | 0.23 / 0.27 / 0.29 ms |
| `bridge.import_cell()` total | 3.90 / 28.50 / 179.95 ms | 3.85 / 4.40 / 5.50 ms |

Cold texture work explains the legacy tail; warm cost is dominated by 1,089
GDScript-to-native pixel writes per cell.

### Native-region and fill gates

- Native WastelandNV index: 16,388 usable cells, 292 regions, 18×18 rectangle,
  80 identities; representative index time 2,087 ms.
- Goodsprings-area region: 11.56 ms / 72 real contributors = 0.161 ms/cell.
- Staging plus p95 publication: about 0.184 ms/cell versus 3.65 ms/cell for
  remeasured warm legacy writes/publication: about 19.8× faster (2× target).
- Fixed publication p95: 1.67 ms over seven recorded samples; later stress
  output: 1.267 ms over four samples. Both are under 16.67 ms.
- Representative stationary WastelandNV fill: approximately 13 seconds.
- Object construction during fill remained within the 10% gate: p95
  2.184 → 2.259 ms (+3.4%); max 13.594 → 14.068 ms (+3.5%); 1,257 samples.

## Plan comparison and remaining work

### Intentional adaptation

Phase 1 described deactivating both streamers for a different exterior
worldspace. Phase 4 retention makes final terrain teardown incompatible with
preserving the outgoing entry. The implementation deactivates object
`WorldStreamer` state, while `TerrainStreamer.activate(destination)` suspends,
generation-invalidates, and retains the outgoing entry before restoring or
creating the destination. `TerrainStreamer.deactivate()` remains the explicit
final teardown. This reconciles the earlier wording with Phase 4 rather than
bypassing lifecycle gates.

The explicit cache list is more complete than the plan's shorthand: it includes
all twelve census-confirmed base-master terrain worldspaces, still within the
selected Mojave/base-game family scope.

### Deliberately unimplemented or unverified

1. DLC master/load-order resolution, DLC cells/doors/transitions, DLC-family
   retention/eviction, global retention, and LRU policy are not implemented.
   Unknown/DLC worldspaces are rejected rather than inferred or evicted.
2. Real GPU memory, GPU fill/upload completion, clipmap distance, graphical
   horizon/silhouette parity, hands-on collision/grass behavior, and
   player-driven door traversal are unverified. This blocks full v1.5 visual
   acceptance.
3. `Landscape\\BurntGround01.dds` is unavailable in the supplied BSAs and uses
   the explicit pink fallback; it is not considered a successful asset resolve.
4. The complete aggregate repository headless suite was not rerun as one command
   during this work; only the focused checks listed above are claimed.
5. The Issue #19 comment was drafted but not posted without separate authority.

## Build and checkout notes

The native streamer is a separate generated binary, intentionally not
committed. Build it after checkout:

```bash
cd native/terrain_streamer
scons platform=linux target=template_debug api_version=4.7 \
  use_static_cpp=no disable_exceptions=no -j$(nproc)
```

The SCons file contains the POSIX archive workaround required for this path and
host `ARG_MAX` limitation; `AGENTS.md` documents it. Initialise the referenced
Terrain3D submodule before building/running:

```bash
git submodule update --init --recursive
```
