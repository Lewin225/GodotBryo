# Phase 0: Terrain3D capability audit and current-path baseline

Status: CPU capability gates complete on 2026-08-26. Graphical/vanilla evidence remains an explicit v1.5 acceptance blocker; see below.

## Capability audit

### Collision is global on region-map changes; only dynamic collision is local

`Terrain3D::_initialize()` connects `Terrain3DData.region_map_changed` directly to `Terrain3DCollision::build()` (`native/terrain3d/src/terrain_3d.cpp:66-69`). `build()` destroys the existing collision body and shapes, then recreates them. It is not a per-region operation.

In `DYNAMIC_GAME` mode, `Terrain3DCollision::update()` does operate around the snapped camera position using a fixed grid of reusable heightmap shapes (`terrain_3d_collision.cpp:286-391`), and Terrain3D calls it after camera motion (`terrain_3d.cpp:127-134`). `FULL_GAME` instead iterates every active region and makes one shape per region (`terrain_3d_collision.cpp:393-411`).

**Decision consequence:** Phase 2 must preallocate the fixed region domain once, paying one initial region-map/collision rebuild, then publish a completed region without changing the region map. After publication it may request/allow the normal camera-local dynamic collision refresh. Rebuilding collision on every background region commit would be structurally wrong.

### Existing Terrain3D APIs cannot provide stable fixed layers on their own

`Terrain3DData::add_region()` always marks `_region_map_dirty` (`terrain_3d_data.cpp:243-269`). The next `update_maps()` reconstructs `_region_locations` from `_regions.keys()` and emits `region_map_changed` (`terrain_3d_data.cpp:520-545`). This has two implications:

1. adding/replacing through the existing public path invokes the global collision rebuild above; and
2. the active layer ordering is rebuilt from a dictionary, so it is not the explicit permanent coordinate-to-layer contract required by plan 1.5.

The planned native batch-publish API is therefore required. It must preallocate stable coordinates/layers in a deterministic order, replace only the eight maps for an already-owned layer, update the generated texture-array layer without making the region map dirty, and emit only the map/material notifications actually required. Calling `add_region()` per completed region is not an acceptable substitute.

### Grass is project-owned and currently scales with every imported cell

Terrain3D itself has no path for this project's GPUParticles grass. `TerrainGrassParticles.observe_cell()` is called after every `Terrain3DBridge.import_cell()` (`world_streamer.gd:620-629`). It discovers LTEX/GRAS data, then rebinds **every** live emitter after each cell because the current material receives Terrain3D's region map by value (`terrain_grass_particles.gd:44-83`). `_bind_variant()` reaches `RenderingServer` directly.

**Decision consequence:** background whole-world fill must not call `observe_cell()` per imported cell. Grass discovery/variant binding needs a batched or near-camera-priority path after the region publication interface exists. This is a correctness/performance requirement, not later polish.

## Fixed-domain publication proof

`Terrain3DData.initialize_fixed_region_domain()` now validates and sorts an intentionally unsorted 2×2 rectangle row-major, creates canonical blank eight-map regions, and publishes the region map once. `publish_region_maps()` rejects locations outside that domain and validates all eight image sizes/formats. `test_terrain3d_batch_publish.tscn` proves a later complete replacement emits each of the eight map-array signals exactly once and emits zero further `region_map_changed` signals. Since Terrain3D connects that signal directly to `Terrain3DCollision.build()`, the audited call graph plus the zero-signal assertion proves ordinary replacement cannot trigger the global collision rebuild.

## Canonical shared-sample ownership

For every sample duplicated at LAND edges/corners, enumerate all cells whose 33×33 payload contains it, discard missing/unusable contributors, sort the remainder lexicographically by `(x, y)`, and select the first. At world edges or gaps this falls through to the next usable contributor. One selected cell supplies height, VCLR, VNML, texture IDs, and weights; fields may never choose owners independently. Phase 2's native `TerrainRegionStager` implements this rule; `test_terrain_shared_sample_owner.tscn` covers interior, X-edge, Z-edge, corner, and missing-lowest-contributor fallback cases, while frozen complete-region hashes cover its composed output.

## Graphical evidence and acceptance boundary

The host exposes a graphical session and an RTX 3080 Ti, but Phase 0 does not yet have the production fixed 18×18 allocation/fill path whose driver allocation or fill frametime would be meaningful to measure. No controlled vanilla capture/save/camera transform was supplied or present in the repository, so a Goodsprings-to-Strip silhouette comparison cannot be reproduced honestly. Accordingly, graphical clipmap distance, real GPU memory, graphical fill frametime, and vanilla silhouette parity are **unavailable and remain explicit blockers to declaring v1.5 fully accepted**. Implementation may continue under the milestone's stated exception, but no graphical or vanilla claim is made here.
