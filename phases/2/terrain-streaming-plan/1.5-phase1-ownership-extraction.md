# Phase 1: terrain ownership extraction

Status: implemented and headless phase gate passed on 2026-08-26. Graphical transition/play validation remains unavailable in this environment and is not claimed.

## Ownership and startup

`game.tscn` now authors `TerrainStreamer` as a direct sibling of `CellLoader` and `WorldStreamer`. `Game._enter_tree()` resolves the data directory, opens one main-thread `EsmReader`, constructs one main-thread `GamebryoMeshResolver`, and calls all three loaders' `configure(esm, resolver)` before their `_ready()` methods. Each loader retains a standalone fallback when no dependency was injected.

`TerrainStreamer` exclusively owns the live Terrain3D node, texture pool, bridge, grass controller, active-camera binding, radius-20 discovery queue, terrain timings, collision refresh, and terrain pause/resume. Phase 1 originally retained the synchronous importer; Phase 2 has since replaced that internal implementation with native complete-region staging without changing this ownership boundary. `WorldStreamer` owns objects only and its only executable terrain interaction is `terrain_streamer.request_terrain_priority(coord)`.

The legacy `use_terrain3d` switch, per-tile `TerrainRoot`, legacy mesh branch, and `CellStreamBuilder.build_terrain()` were removed. `CellLoader` no longer creates exterior terrain either.

## Lifecycle and readiness

The implemented API is:

```gdscript
configure(esm, resolver)
activate(worldspace_form_id)
deactivate()
set_paused(paused)
request_terrain_priority(coord)
await_ready_for(worldspace_form_id, coord, generation) -> ReadyStatus
get_diagnostics() -> Dictionary
```

Readiness returns `READY`, `CANCELLED`, or `SUPERSEDED`. Its first successful path verifies every usable LAND cell in the dynamic-collision circle is committed, rebinds the current camera, refreshes dynamic collision, and crosses one physics frame before caching readiness. A repeated ready request uses the cached path. Pause cancels the current generation; teardown or worldspace replacement supersedes it.

`Game` owns an independent transition generation. Interior entry cancels/pauses terrain before object streaming. Same-worldspace exterior return restores terrain before objects. A different worldspace deactivates both owners, repositions the player, activates terrain and objects, and releases physics only when the current transition has both object settlement and `READY` terrain status. The release predicate is directly regression-tested against stale, cancelled, terrain-only, and fully-ready cases.

## Diagnostics

The World Streaming debug tab continues to display object state and tuning. Terrain resident/queue counts and texture entries now come through `TerrainStreamer.get_diagnostics()`; the tab no longer reads a private terrain pool from `WorldStreamer`.

## Verification

`test_terrain_streamer_phase1.tscn` uses real WastelandNV data and proves:

- the extracted radius-3 test domain commits the expected 29-cell circular set (the production default remains radius 20);
- the Phase 2 replacement preserves the same 29-cell desired set and publishes complete eight-map regions (byte parity now lives in `test_terrain_region_stager`'s frozen oracle hashes);
- first readiness includes collision refresh plus a physics frame, and repeated readiness uses the cache;
- pause returns `CANCELLED`, teardown returns `SUPERSEDED`;
- executable `WorldStreamer` code contains no Terrain3D/bridge/grass implementation access and has exactly one terrain call, the priority hint;
- the scene-authored sibling exists and stale/cancelled/incomplete transitions cannot release the player.
