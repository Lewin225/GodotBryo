# Phase 4: retained Mojave-family terrain lifetime

Status: implemented for the `FalloutNV.esm` Mojave/base-game cache family. DLC runtime transitions, load-order resolution, and eviction remain deliberately unsupported.

## Retained runtime entries

`TerrainStreamer` now keeps a registry keyed by worldspace FormID. Each entry owns its `Terrain3D`, `Terrain3DBridge`, `Terrain3DTexturePool`, grass controller, native catalogue, frozen logical slots, fixed-region maps/queues/state, generation, residency, worker-stager pool, and diagnostics. The shared `Game` ESM reader and mesh resolver remain shared decode sources only; no Terrain3D map or texture-binding state is shared between entries.

Cache membership comes from an explicit EditorID catalogue resolved at configuration time, not FormID prefixes. It enumerates all twelve terrain-owning base-master worldspaces from the Phase 0 census: `TestMap01`, `WastelandNV`, Freeside/Gamorrah/Greenhouse subworlds, the Strip/Fort/Boulder City subworlds, `WastelandNVmini`, and `Lucky38World`. Unknown worldspaces, including DLC-family records, are rejected by this v1.5 runtime rather than inferred or evicted.

`activate(worldspace)` now suspends the outgoing entry rather than freeing it, then restores an existing entry or creates a new one. `deactivate()` remains the explicit final teardown and frees all retained entries.

## Inactive/resume lifecycle

Suspension first advances the entry generation and marks queued/preparing/prepared regions cancelled. Detached tasks are abandoned and globally reaped, so no stale payload can publish. The retained Terrain3D is then hidden, physics processing disabled, and dynamic collision disabled. Its grass controller is hidden/stopped and every emitter is non-emitting.

Resume restores the saved entry, visibility, active camera, Terrain3D physics processing, dynamic collision, and grass processing—in that order. It performs a local coverage update before restarting only covered emitters, requeues only uncommitted regions, and rebuilds worker capacity under a fresh generation. Completed maps, fixed arrays, bridge slots, texture assignments, and diagnostics are preserved without LAND staging or publication.

## Automated evidence

`test_terrain_streamer_phase4_retention.tscn` exercises a real master-data round trip:

1. Fill WastelandNV to 292/292 committed regions.
2. Switch to `FreesideWorld` and verify a distinct Terrain3D/bridge/pool stages independently.
3. Assert the retained Wasteland entry has no visibility, Terrain3D physics, collision, grass processing, or emitting particles; its collision/grass counters remain unchanged while Freeside is active.
4. Return to WastelandNV and verify the original Terrain3D/bridge/pool identities, a sampled height-map SHA-256, and logical-slot mapping are unchanged.
5. Verify collision-safe readiness returns and the fully completed Wasteland entry records no new staging or publication.
6. Verify a Freeside worker that completes after its generation is superseded cannot commit into the inactive entry.
7. Verify final `deactivate()` releases both retained entries.

The Phase 1 lifecycle, Phase 2 worker stress, and Phase 3 finite-fill tests continue to cover same-worldspace interior pause/resume, generation cancellation, publication safety, and completion behavior.
