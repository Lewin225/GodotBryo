Record Schema · Field Manual

The Mojave Data Model

Fallout: New Vegas's entire world — every door, raider, quest, and bent tin can — is built from roughly 145 record types inside FalloutNV.esm. This is a working reference to the core ones: what each record actually is, the fields that define its behavior, and how it relates to the others. Compiled for this project's own Godot port, so each section also notes what's already real in this codebase versus what's still just data on disk.

00 Foundations

Two ideas underlie everything below. Get these wrong and every other record in the game misreads.

Object → Reference

An Object (a.k.a. Base Form) is the template — one STAT record for "NCR guard tower," one NPC_ record for "Doc Mitchell." Whenever an object is placed in the world it's instantiated as a Reference (REFR, or ACHR/ACRE for actors) — modelled after the object, but carrying its own extra data: position, health, ownership, whatever makes this particular instance different from every other placement of the same base form.

This project already leans on the distinction directly — GamebryoMeshResolver caches every resolved mesh/texture/material by the base object's path, since a cell routinely places the same rock or fence post dozens of times; only the transform is per-reference.

The Inventory Quirk

When an item Reference is picked up into a container or inventory, the reference itself stops existing — but its extra data (condition, count, hotkey) is folded into the inventory entry first. Drop it again and a new Reference is synthesized from that stored data. This is why a hotkeyed weapon loses its hotkey when dropped and re-equipped: the hotkey lived on the reference, and the reference that held it is gone the moment it hits the ground.

01 World Objects

Everything physically placeable that isn't an actor or a piece of terrain falls under WorldObjects in the GECK's own taxonomy. All of them share a Model field, an optional destructible-object stage list, and (for animated ones) a Random Anim Start flag so duplicate placements don't animate in visible lock-step.

DOOR

Door

Registered · DOOR

A specialized Activator with built-in teleport behavior. Animating doors just play an open animation on activation; load doors resolve an XTEL link to a destination reference (usually another door) and teleport the actor there — this is the exact mechanism this project's Freeside softlock investigation traced through game.gd's _do_exterior_transition().

FieldWhat it does
Open/Close/LoopSound triggered on state change — usually left blank on baseforms since animated doors bake sounds into the NIF via NiTextKeyExtraData; setting both is the classic "double sound" bug.
Automatic DoorAuto-teleports the player once within fAutoDoorActivateDistance. Setting this on a non-load door freezes the player permanently — a documented engine bug, not a rare edge case.
Random destination listWhen populated, the actual destination isn't chosen until first activation, then saved with the save file. Reloading a pre-activation save re-rolls it.
Sliding DoorSkips navmesh obstacle generation — NPCs will walk through it even closed.
CONT

Container

Registered · CONT

Holds an item list of (Object, Count, Health%, Owner) tuples, including LeveledItem entries for level-scaled loot. Container Havok geometry can be non-static, letting the player shove a footlocker around. Each item can be owned by an NPC or Faction — taking it then counts as theft against that owner specifically.

FieldWhat it does
RespawnsRecomputes leveled-item contents after iHoursToRespawnCell, unless the owning Encounter Zone is flagged Never Resets.
Required RankMinimum faction rank to count as a legitimate owner of an item inside.
ACTI

Activator

Registered

Anything usable by an actor: levers, water sources, radios, scripted triggers via OnActivate. Requires a Name to be interactable at all — an unnamed activator can't be activated by the player, full stop.

TACT

Talking Activator

Unregistered

An Activator that can run dialogue and own a Voice Type — the record behind radios and intercoms. Casino ambient music in FNV specifically uses the Non-Pipboy flag so the station exists without being tunable from the Pip-Boy.

FURN

Furniture

Registered

Anything an NPC has an animation for using — chairs, beds, wall-lean markers. Tables and shelves stay STAT; the distinction is purely "does an actor have an anim for this," not visual function. Furniture references must be persistent or AI Packages can't reliably use them.

STAT

Static

Generic fallback

Fully inert geometry — no Havok, no script, can't be destroyed. Buildings, walls, terrain dressing. This project's registry already treats "has a resolvable Model, no registered factory" as the generic-visual path, which is functionally the STAT case even though it isn't a named factory.

MSTT

Movable Static

Unregistered

Statics that do get Havok — grabbable, blast-movable clutter, plus looping single-animation FX objects (usually FX-prefixed: sprays, flames, smoke). This project's own mesh-resolver doc notes MSTT placements are unregistered today and fall through the RID-based structural path rather than a Node.

LIGH

Light

Registered

A spherical illumination source, optionally carryable (the Pip-Boy light uses this via a Base Effect with the Light archetype rather than the raw record). May or may not have an attached 3D model — a bare light with no mesh is common for fill lighting.

TERM

Terminal

Unregistered

A World Object built around a hackable menu tree: Welcome Text, then up to ~7–8 Menu Items (each with its own result text, optional Note display, optional nested submenu terminal, and Conditions). "Top-level" terminals are the placed activators; "submenu" terminals exist purely to host a menu-item list referenced from another terminal's Sub Menu field — there's no engine-level distinction, just convention. Locked terminals gate on the hacking minigame or possession of a password Note; failing the minigame locks it out permanently barring the password.

TREE

Tree

Unregistered

Authored in SpeedTreeCAD and imported as .SPT, not a NIF — a genuinely distinct asset pipeline from every other WorldObject. Covers ordinary trees and a wide variety of non-tree plants alike.

GRAS

Grass

Unregistered

Painted onto landscape vertices via a LandTexture assignment, not placed as references at all — density, slope range, and color/height jitter are all per-vertex-random and regenerated per session rather than save-baked.

PWAT

Placeable Water

Unregistered

Hand-placed water planes (mainly for interiors), with explicit Reflects/Refracts reference lists rather than automatic reflection — nearby statics have to be manually linked in the "refracted by" tab to actually appear through the water.

ECZN

Encounter Zone

Unregistered

Groups cells/worldspaces/references into one leveled area. Its Zone Level is computed once, on first player visit, and never recalculated — every leveled list inside resolves against that frozen value, not the player's current level.

CLMT

Climate

Unregistered

Per-worldspace definition of sun/moon behavior, sunrise/sunset timing, and a weighted table of eligible WTHR records with a volatility slider controlling how often the active one changes.

WTHR

Weather

Unregistered

Nine color slots (ambient, fog, horizon, sky upper/lower, sun, sunlight, stars, cloud layer) each keyed across six times of day, plus fog near/far/power curves and an associated ImageSpace Modifier per time-of-day. This project currently swaps one flat interior/exterior Environment resource rather than reading WTHR at all.

Static Collection (SCOL) is a real, load-bearing FO3/NV record — this project's own _build_scol() factory handles it — but it did not surface in the automated fopdoc capture used for this document's appendix. Treat the appendix as a strong starting index, not a substitute for fopdoc itself when precision matters.

02 Actors: NPCs & Creatures

Actors are the subset of objects that run AI — they move, fight, and interact with doors/containers/other actors. Every actor is one of NPC_, CREA, or a Leveled Character/Creature template resolved into one of those two at spawn time; a TalkingActivator counts as an honorary fourth case since it can carry dialogue and a voice like a full actor. NPCs and Creatures share most of their tab structure (Traits, Stats, Factions, AI Data, AI Packages, Inventory, Actor Effects, Animation, Blood, Destruction, Scripts) but differ in two structural ways worth knowing up front.

NPC_

Non-Player Character

Unimplemented

Can wear ARMO/clothing, can appear in LeveledCharacter lists, always supports dialogue and pickpocketing. The Player is a special-case NPC_ driven by input instead of AI. Placed in the world as an ACHR reference.

No actor system exists in this codebase yet — the ESM parser reads WRLD/CELL/REFR/LAND/LIGH/LTEX explicitly and passes every other base record's raw signature through generically as base_type, but the object registry has no ACHR handling: an NPC reference falls through to "has a resolvable model" (false, since NPCs use a race/skeleton, not a MODL) and is silently skipped.

CREA

Creature

Unimplemented

Cannot wear armor and never appears in LeveledCharacter lists, but runs its own separate skeleton/animation system — giving creatures more VATS-target and appearance variation than NPCs get. Can still hold dialogue, act as a companion, or run a vendor just like an NPC despite the different rig. Placed as an ACRE reference.

Shared Actor Flags

FlagWhat it does
EssentialNever dies outright; goes unconscious instead, still lootable, no special death message.
RespawnReference is recreated three days after death/removal.
No Low Level ProcessingAI only updates while the actor shares the player's loaded area — the standard far-away-NPC cost-saving flag.
Quest ItemUpdates more frequently and skips cell-reset cleanup; a dead body carrying any quest-item inventory entry also won't despawn until that item is removed, regardless of the actor's own flag.
No Knockdowns / No VATS MeleeThe latter is misleadingly named — it has nothing to do with VATS, it stops other actors from melee-targeting this one.

Template Data lets one actor inherit whole tabs (Traits, Stats, Factions, AI Data/Packages, Inventory, "Use Model/Animation" — which bundles Blood, Sounds, and Destruction) from another actor listed as its ActorBase, including a LeveledCharacter/LeveledCreature. This is the mechanism behind most of the Mojave's enemy variety: dozens of raiders sharing one base template with only cosmetic/equipment overrides.

03 Leveled Lists

Three record types — LVLN (Leveled Character), LVLC (Leveled Creature), LVLI (Leveled Item) — all resolve which entry to pick against player level (items, and container/vendor NPC-owned lists) or the owning actor's own level (an actor's inherited inventory). None of the three can be placed directly in the world: Leveled Character/Creature only work as an actor's Template, and Leveled Item only works inside a container or an actor's inventory.

SettingBehavior
Calculate from all levels ≤ PC's levelAny entry at or below the resolving level is eligible; unchecked picks only the closest entry not exceeding that level.
Use All (items only)Every entry is added regardless of level — supersedes both level-calc checkboxes.
Chance None (items only)Flat chance the list resolves to nothing at all.
CountOn items: how many copies of the resolved entry to create. On actors: unused, must be 1.
Difficulty Modifier (reference-side, actors only)Easy/Medium/Hard/Boss/None locks the resolved level to 50/75/125/200/unlocked% of the space's own resolved level — visualized in the editor as a white/green/yellow/orange/red marker.
A real crash condition, not a style nit: every leveled list needs at least one level‑1 entry, or the game crashes on startup when nothing in the list qualifies for a low-level resolve.

04 Weapons, Armor & Items

Anything that can occupy a container slot is an Item, sharing a common shape — Inventory Image, Message Icon, Model, Equip Type, Weight, a Quest Item flag — before each subtype layers its own behavior on top.

WEAP

Weapon

Unimplemented

The densest item record in the game: General/Flags/Game Data/Art&Sound/Rumble/Mod Info/DPS tabs. Damage, Min Spread (the actual spread driver — the legacy "Spread" field is dead in New Vegas), Crit % Mult, an optional Object Effect applied only once the hit deals ≥1 damage, and up to three Weapon Mod (IMOD) slots that swap models outright rather than compositing geometry — three mods means eight pre-baked model variants, not additive attachments.

ARMO

Armor

Unimplemented

DR (0–fMaxArmorRating, default 85), DT, and up to 19 Biped Object slots (Head, Hair, UpperBody, Hat, Necklace, Backpack, and so on) that determine what else gets hidden or occupied when this piece is worn. Creatures can hold armor in inventory but can never equip it.

ARMA

Armor Addon

Unimplemented

Pure 3D-geometry accessories (necklaces, backpacks, masks) attached via a FormList on the parent Armor's Biped Model List. Contributes zero weight/health/value/scripts of its own — it's purely a visual layer riding on the armor that references it.

AMMO

Ammunition

Unimplemented

FNV added per-ammo-type overrides on top of the base record: a substitute Projectile, a projectiles-per-shot override, an Impact Script that runs on struck actors before any Ammo Effects, and a weight field relevant only under Hardcore mode.

ALCH

Ingestible

Unimplemented

Anything consumable — food, chems, Stealth Boys. An Ingestible with only detrimental and hostile effects is classified as a poison. Only Base Effects flagged "Self" are legal here.

BOOK

Book

Unimplemented

No readable text in the base game — "using" a book instantly grants a flat bump to its Teaches actor value. FNV's skill magazines are ALCH Ingestibles, not Books, despite the in-fiction framing.

MISC

Misc. Item

Unimplemented

Havok-physical, has weight and value, otherwise functionally inert unless a script is attached — the catch-all for scrap, junk, and crafting components.

KEYM

Key

Unimplemented

Weightless, unsellable, shown on a dedicated in-inventory Keyring. Its Value field is repurposed entirely — it weights pickpocket detection odds, not price.

NOTE

Note

Unimplemented

Picking one up auto-files it in the Pip-Boy as text, an image, or a sound-with-graphic. GetItemCount always returns 0 for notes — GetHasNote is the only reliable check.

FNV-specific item types not tracked above: Caravan Card (CCRD, an individual playing card for the Caravan minigame, with high-res face/back texture fields) and Casino Chip — both real, playable-item records; the GECK Wiki's own Casino Chip article is itself a stub with no field documentation yet.

05 Game & Special Effects

Everything that modifies an actor's stats or triggers a script traces back to one MGEF Base Effect. Three wrapper records apply a Base Effect to something concrete: an Actor Effect (SPEL, a "spell") targets an actor directly, an Object Effect (ENCH) rides on a weapon or piece of armor, and an Ingestible's own effect list applies on consumption. All three share the same underlying Effect Item shape: which Base Effect, at what Range/Area/Duration/Magnitude, gated by optional Conditions.

MGEF

Base Effect

Unimplemented

Behavior comes from a hard-coded Archetype — Value Modifier (alter an actor value), Value and Parts (alter a value and distribute it across limb condition, e.g. Stimpaks), Paralysis, Script (run an attached Effect-type script), Chameleon, Light, and several archetypes ("Dispel," "Invisibility," "Lock/Open," "Summon Creature") that exist in the editor but are unused anywhere in the shipped game.

EFSH

Effect Shader

Unimplemented

A Membrane Shader (applied to the target's own mesh, blend-mode driven — e.g. Src = Source Alpha / Dst = Source Inverted Alpha for ordinary alpha blend, or Src = One / Dst = One for a brightening additive look) plus an optional Particle Shader emitted from the target. The exact combinatorial blend-mode question this project already solved for real NIF materials, but authored here per-effect instead of per-NiAlphaProperty.

EXPL / PROJ / IPDS

Explosion, Projectile, Impact Data Set

Unimplemented

A Weapon references a Projectile; a Projectile can carry an Explosion; an Impact Data Set maps material types (stone, flesh, metal…) to the correct decal/sound/particle response on hit, so one weapon's impact reads differently on concrete versus a super mutant.

06 Quests, Dialogue & Factions

This trio wasn't in the saved GECK Wiki set for this pass — summarized here at the fopdoc/record-signature level rather than the same field-by-field depth as the sections above. Worth a dedicated follow-up pass if these become load-bearing for the port.

QUST

Quest

Unimplemented

A stage-based state machine: numbered stages carry result scripts and log entries, quest objectives track target references/locations, and Conditions gate which stages are currently reachable. Every quest-driven scene, companion, and faction-reputation shift in the game ultimately threads through a QUST record's stage log.

DIAL / INFO

Dialog Topic / Response

Unimplemented

A DIAL topic groups a branching tree of INFO response records, each with its own Conditions, response text, voice line, and optional result script. Terminal menu items reuse this same Conditions vocabulary independently, without going through DIAL/INFO at all.

FACT

Faction

Unimplemented

Defines a rank ladder, relationships to other factions (ally/neutral/enemy, each with its own numeric modifier), and crime-gold tracking. Container and Encounter Zone ownership, Ammo/Weapon "faction currency" items, and companion recruitment all key off Faction membership and rank rather than anything on the NPC record itself.

07 Miscellaneous & World Systems

Support records that don't place in the world themselves but that almost everything above depends on.

SigNameRole
FLSTFormListAn ordered, typeless bag of form references — the plumbing behind Armor's Biped Model List, a Weapon's acceptable-ammo list, repair-item lists, and dozens of other "pick from this set" fields.

SOUNSoundA sound file plus attenuation/randomization data — referenced by nearly every other record type (doors, containers, weapons, weather) rather than placed on its own.

09 This Project's Coverage

Grounded directly in the current source, not aspirational: what native/src/esm actually parses, and which base_types GamebryoObjectRegistry has a real factory for.

SignatureStateDetail
WRLD / CELL / REFR / LAND / LTEXParsedExplicitly handled by the ESM reader — the whole world-streaming and cell-loading pipeline runs on these five.
LIGHParsed + RegisteredExplicitly parsed by the ESM reader, and object_registry.gd has a dedicated _build_light() factory.
DOOR / CONT / ACTI / FURNRegisteredNot individually parsed at the ESM-record level — instead the base record's raw 4-char signature flows through generically as base_type, and these four have dedicated factories in _register_defaults().
SCOLRegisteredHas its own _build_scol() factory — confirmed present in this project's real data despite the appendix-table gap noted above.
STAT / everything else with a MODLGeneric fallbackAny base record with no registered factory but a resolvable Model path becomes a plain GamebryoVisual — visually correct, but with none of the type-specific behavior (destructible stages, container inventories, door teleports) that a real factory would add.
NPC_ / CREA / ACHR / ACREUnimplementedNo actor system at all: no AI, no dialogue, no factions, no combat. A placed NPC/Creature reference has no MODL of its own, so it fails even the generic-visual fallback and is silently skipped by build().
LVLN / LVLC / LVLIUnimplementedNo leveled-list resolution logic exists — moot until actors/items themselves are real.
QUST / DIAL / INFO / FACT / PACKUnimplementedNo quest state machine, no dialogue tree traversal, no faction reputation tracking, no AI packages.
WEAP / ARMO / AMMO / ALCH / everything under ItemsUnimplementedNo inventory system exists to hold them yet — a prerequisite this shares with the actor gap above.
TACT / TERM / TREE / GRAS / MSTT / PWAT / CLMT / WTHR / ECZNUnimplementedReal WorldObject subtypes with no registered factory yet — each would fall through to the generic-visual path today if it happens to carry a MODL, or be silently skipped if not.
