Rollout Plan

The Mojave Build Plan

Two people can start today, in parallel, with no coordination beyond agreeing on one small contract up front. This is that plan: what each track builds, in what order, and the exact steps that bring them back together.

Fourth of four companion documents — sits downstream of the Mojave Data Model, Mojave Class Hierarchy, and Mojave Script Interpreter design notes.

00 The one thing to agree on first

Both tracks depend on a single narrow interface: what the interpreter's ExecutionContext needs from whatever object a script is attached to. Agree on this shape before either track starts, and the merge later is a swap, not a rewrite.

Calling-Reference Contract

get_form_id() -> intIdentity — needed for symbol resolution and debug output.
get_local_var(name) / set_local_var(name, value)Per-instance script-local variable storage — a different value per Reference running the same Object script.
is_persistent() -> boolGates cross-reference MyRef.MyVar access — only persistent references expose their variables remotely.
get_editor_id() -> StringFor error messages and the fallback symbol lookup when SCRO/SCRV doesn't already resolve a name.

Track B builds a tiny mock class satisfying exactly this shape and never needs anything from Track A to make progress. Track A's real GamebryoReference/ GamebryoObject/GamebryoActor chain just needs to satisfy the same four members once it exists — the interpreter never knows the difference.

01 The two tracks

Track A

Nodes / Objects / RefCounted

Builds the real class hierarchy. No dependency on the interpreter existing.

GamebryoReference: StaticBody3D → Node3D

The root change everything else in this track depends on — keeps the transform, drops the physics-body assumption.

Internal StaticBody3D child on GamebryoVisual

Retarget populate_collision_children() and game.gd's interact raycast to walk from the physics-body child up to its owning reference.

Regression pass

Confirm DoorNode/ContainerNode/ActivatorNode/FurnitureNode/LightNode/SCOL all still collide and interact correctly post-refactor before building anything new on top.

GamebryoActor, sibling of GamebryoVisual

Extends GamebryoObject directly; adds its own internal CharacterBody3D child — same composition trick as step 2, for movement instead of static collision.

NPCNode / CreatureNode stubs

Thin leaves satisfying the Calling-Reference Contract above — real AI/dialogue can come later, but the contract needs to be live early since Track B's merge step depends on it.

Quest / Faction / LeveledList as Resources

Resource-backed, cached by form ID/editor ID the same way _nif_cache/_image_cache already work — never Nodes, per the class hierarchy doc's own rule.

ESM parsing for NPC_/CREA/QUST/FACT/LVLN/LVLC/LVLI native

Real new C++ parser + GDExtension binding work, not just GDScript — feeds the Resources/Nodes from steps 4–6.

Register new base_types

Wire NPC_/CREA (and eventually the others) into GamebryoObjectRegistry's factory table, same one-line-per-type pattern DOOR/CONT/ACTI already use.

Track B

Parser / Interpreter

Builds the language engine. Tested entirely against real SCTX text and a mock reference — zero dependency on Track A's classes existing.

Mock calling-reference stub

A small class satisfying the Calling-Reference Contract — this single class unblocks every other step in this track.

Lexer

Tokens: keywords, identifiers, numbers, operators, comments stripped. Test directly against real SCTX samples pulled from FalloutNV.esm — no synthetic fixtures needed, the real data is already on disk.

Parser → AST

ScriptDef, an ordered list of (blocktype, params, stmts) blocks, statements, expressions — covers set/let, if/elseif/else/endif, begin/end, comments, no switch/case.

Symbol resolution against SCRO/SCRV

May need a small ESM-reader addition to expose SCPT's SLSD/SCVR/SCRO/SCRV subrecords if not already surfaced — flag this as a possible native-layer touchpoint with Track A, the one place the two tracks' native work might overlap.

Tree-walking Interpreter + ExecutionContext

Tested entirely against the mock from step 1 — a real script can be parsed and executed end-to-end here without a single Track A class existing yet.

Wire Expression for leaf arithmetic/comparison

Godot's own Expression.parse()/execute() for the sub-expressions inside if/set — not control flow, not statement-level calls.

Function dispatch table, stubbed

The ~30 Tier-1 built-ins (Enable, AddItem, MoveTo, Activate...) registered as no-op/print-debug Callables — proves the whole pipeline dispatches the right function with the right args, without needing real behavior yet.

GameMode/MenuMode on a test tick

Hook block execution to a manual tick or SceneTree.process_frame in a test harness — not WorldStreamer._process() itself yet, that wiring is a merge-phase step.

02 Merge phase

Starts once both tracks have their own milestones done. Small by design — the contract from step 00 is what makes it small.

Bringing Track A and Track B together

Swap the mock for the real reference chain

Point Track B's ExecutionContext at real GamebryoReference/GamebryoObject/GamebryoActor instances. If the contract held, this is a one-line change per call site, not a rewrite.

Implement the real Tier-1 function bodies

Replace each stub Callable with real behavior calling into Track A: Enable/Disable toggle the real node, AddItem calls the real inventory, MoveTo repositions the real node, Activate calls the real activate() contract game.gd's interact raycast already uses.

Hook GameMode into the real frame loop

Swap the test-harness tick from Track B step 8 for the real WorldStreamer/game.gd cadence.

Wire Quest-script variables into the real Resource cache

Connect MyQuest.MyVar access to Track A's real Quest Resource lookup table from Track A step 6.

Run one real script from the ESM, in play

Pick one of the Tier-1-only scripts already sampled during the interpreter research pass, attach it to a real placed object in a loaded cell, and confirm it behaves correctly — the actual acceptance check for this whole plan.
