Architecture Notes

The Mojave Script Interpreter

Every SCPT record, every OnActivate/OnDeath/GameMode block — the part of this port that actually runs the game. The central decision below is verified against real bytes in this project's own FalloutNV.esm, not assumed from documentation.

Third of three companion documents, alongside the Mojave Data Model (record reference) and the Mojave Class Hierarchy (Node design).

01 Don't decode Bethesda's bytecode

A compiled SCPT record carries several subrecords. Read byte-for-byte from a real record in this project's own ESM (VLCSafetyTrigger01SCRIPT, picked at random): 

EDID  25   "VLCSafetyTrigger01SCRIPT"
SCHR  20   refCount, compiledSize, lastIndex, scriptType, scriptFlags
SCDA  400  <compiled bytecode — Bethesda's own proprietary VM format>
SCTX  1268 "scn VLCSafetyTrigger01SCRIPT\r\n\r\nRef ActivatorREF;\r\n\r\nBEGIN OnTriggerEnter\r\n..."
SLSD  24   local variable slot 1 (index, type flags)
SCVR  13   "ActivatorREF" — that slot's name
SCRV  4    which SLSD slot this SCRO entry resolves for
SCRO  4×8 FormIDs referenced by name in the script text
Verified, not assumed: SCTX — the original, human-readable source — is present and complete on every one of 11,483 scripts sampled directly across the whole ESM, a full scan, not a handful of spot checks.

SCDA, the actual bytecode Bethesda's runtime executes, is also present — but there's no reason to ever decode it. The interpreter should tokenize and parse SCTX directly, the same way the GECK's own compiler did, and never touch SCDA at all. Reverse-engineering a proprietary bytecode VM buys nothing when the real source is sitting right next to it, already in a syntax fully documented by the GECK Wiki.

SLSD/SCVR and SCRO/SCRV are worth keeping too, even though they're derivable by parsing SCTX yourself: they're Bethesda's own pre-resolved symbol table. A hand-rolled parser has to resolve ActivatorREF or a quest editor ID against the whole ESM's namespace at parse time — the compiler already did that once and left the answer in the record.

02 Three flavors, one grammar

Every script (except a bare Result script fragment — no ScriptName, no blocks, just a snippet run once) declares its type at compile time, and the type gates which block types and calling conventions are legal.

FlavorAttached toReference script?Notable rule
ObjectNPCs, Creatures, Activators…YesRuns even for disabled references; GameMode/MenuMode fire every frame, no configurable delay
QuestQUST onlyNoCan't use implicit-reference syntax at all; own configurable processing delay (default 5s)
EffectBase Effect via Actor/Object Effect or IngestibleYes — on the targetLimited to exactly three blocktypes; variables can't be accessed remotely

"Reference script" vs. "non-reference script" is the single most consequential distinction in the language, because it decides whether a call needs an explicit target: 

GetFactionRelation player          ; implicit -- only legal in a reference script
LucasSimmsRef.GetFactionRelation player   ; explicit -- legal anywhere, always names the reference

Mapped onto this project's class hierarchy: an Object script's calling reference is the GamebryoReference/GamebryoActor node it's attached to — implicit calls resolve to self, the way game.gd's interact raycast already resolves its collider. A Quest script has no such self at all — the Resource-based, never-a-Node case from that document; its calling references always come from a local ref variable or an explicit lookup.

03 Variables: three types, four storage tiers

int   varName    ; alias: short, long -- identical, 32-bit signed
float varName    ; single precision
ref   varName    ; a FormID -- either a Reference or a Base Form
TierSyntaxRuleMaps to
LocalmyVarPrivate per Reference running the same Object scriptA field on the interpreter's per-instance execution context
Cross-referenceMyRef.MyVarOnly reachable if MyRef is persistentOwning node's own local-variable table
Quest-scopedMyQuest.MyVarSurvives the quest being stopped — "stopped" only halts processingThe Quest Resource
GlobalGLOB formStored as float internally even when declared Short/Long — high-magnitude int comparisons can silently fail after arithmeticA Resource-backed lookup table by editor ID
A ref can hold either a live Reference or a bare Base Form, and the two aren't interchangeable — calling a reference function through a ref holding only a Base Form is a real, documented crash risk. The idiomatic vanilla guard, if IsFormValid rRef then if IsReference rRef, should be a first-class runtime check the interpreter enforces on every call, not something the script author has to remember.

04 Grammar sketch

statement      := assignment | conditional | block | bare-call | comment
assignment     := ("set" IDENT "to" expr) | ("let" lvalue ":=" expr)
conditional    := "if" expr stmt* ("elseif" expr stmt*)* ("else" stmt*)? "endif"
block          := "begin" blocktype param* stmt* "end"
call           := [reference "."] funcname arg*
comment        := ";" .*                    /* */ block comments are xNVSE 6.2.1+, not vanilla

Operators, exactly as documented — there is no switch/case in this language, by design, confirmed directly in the beginner tutorial:

Arithmetic / Comparison

+  -  *  /  %
==  !=  >  <  >=  <= — always yield exactly 1 or 0

Logical / Truthiness

&&  || — no native NOT/XOR (A == 0, (A||B)-(A&&B) are the idioms). 0 is false, anything else is true.

06 The function library: a registry, not a rewrite of 488

The GECK Wiki catalogs 488 built-in functions before any NVSE extensions — the wrong shape to document exhaustively here. What matters architecturally is that this project already has the right pattern: GamebryoObjectRegistry's _factories is a runtime-populated String → Callable dictionary, grown by calling register(), zero compiled-in switch statement. A script function table is the same shape.

Real usage frequency, counted directly across every script in the ESM (filtered to exclude keywords/blocktypes/project-specific reference names) — each of these appears 400+ times:

07 Proposed pipeline

SCTX (plaintext, already in the ESM)

The source, exactly as the GECK's own compiler saw it — no decoding required.

Lexer

Tokens: keywords, identifiers, numbers, operators; comments stripped.

Parser

AST: one ScriptDef per SCPT, blocks as a flat ordered list of (blocktype, params, stmts).

Symbol resolution

Cross-check identifiers against SCRO/SCRV first; fall back to a live editor-ID lookup only for names the compiler's own table didn't cover.

Interpreter

Tree-walking, not bytecode — a per-instance ExecutionContext holds the local variable table plus a reference to the calling GamebryoReference/GamebryoActor (or null, for a Quest script's non-reference context).

Frame integration

GameMode/MenuMode bodies run on the existing frame tick, not a second timer; Quest scripts get their own SetQuestDelay-driven timer instead.

Tree-walking over the parsed AST matches both what the source data actually gives us (real, readable SCTX, not opaque SCDA) and this project's established preference for verified-format parsers over reverse-engineered binary reimplementations — the ESM/NIF/BSA readers are all real-format parsers, never black boxes.

08 How close to GDScript should this be?

Close in three specific ways, deliberately far in two others — not an all-or-nothing question.

Close — implementation language

GDScript, not C++. This project already states its own split — heavy GDExtension for performance-critical work, GDScript for game-logic glue (direct_geometry_batch.h's own doc comment) — and FNV scripts are exactly the glue-logic case: event-driven, mostly idle between frames, nothing like the tight per-vertex loops that justified C++ elsewhere.

Close — function dispatch

Every built-in should be a real GDScript function in a String → Callable table — the same pattern GamebryoObjectRegistry._factories already uses. Enable/Disable toggle the node the way set_collision_disabled() already does; Activate calls the same contract the interact raycast already uses. The interpreter looks up and calls existing game logic — it doesn't reimplement it.

Close — data representation

int/float map straight onto GDScript's own primitives; ref maps onto either a Node reference or a plain form-ID int — no separate boxed-value wrapper type needed.

Far — don't transpile and hot-compile

Tempting: parse FNV script, emit .gd text, load it at runtime. Resist it — Godot's compiler isn't a sandboxed target, generated-code bugs are miserable to debug, and it gives up exactly the control needed here: capping a runaway loop, enforcing the silently-stop-don't-crash rule on a bad ref, single-stepping a block for a debug overlay.

Far — but don't hand-roll the expression grammar either, where a real Godot API already does the job. Godot ships an Expression class built for exactly this — runtime-evaluated arithmetic/comparison/logical expressions with named variable bindings, confirmed present in this project's own Godot version (native/godot-cpp/gen/include/godot_cpp/classes/expression.hpp): 

Error   Expression.parse(String expression, PackedStringArray input_names = [])
Variant Expression.execute(Array inputs = [], Object base_instance = null, ...)

Use it for the leaf expressions inside if/set — not the whole script. It has no concept of Begin/End blocks, and FNV's own space-separated, no-parens call syntax (AddItem Caps001 10) isn't valid Expression syntax either, so the project's own parser still owns control flow and statement-level function calls. Expression just removes the need to hand-write an operator-precedence parser for the arithmetic/comparison sub-expressions that appear inside them.

09 Explicit non-goals for a first pass

  • NVSE arrays/strings/lambdas/Let/ForEach/UDFs. Real and eventually worth having, but an extension layer on top of the vanilla grammar above — not required to run Bethesda's own base-game scripts. All 11,483 sampled scripts are vanilla-syntax SCTX.
  • Console-only functions. The 38 Designer Debug Tools commands and the broader console-function set never appear in SCTX bodies at all — a separate REPL surface, not part of the interpreter proper.
  • All 488 catalogued functions up front. Build the real-usage Tier 1 list, verify each against actual call sites, grow the registry the same incremental way object_registry.gd already does — not a single 488-function push.
  • Decoding SCDA. Worth repeating as an explicit non-goal, not just an omission: there is no reason to ever touch it.
